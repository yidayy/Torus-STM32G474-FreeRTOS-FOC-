# 项目方案：带本地 HMI 的 FOC 伺服节点

> 硬件：GenBotter ST-12（STM32G474VET6 / LQFP100）
> 代码基线：本仓库（FOC + FreeRTOS 已就位，缺 HAL 外壳）
> 原理图：[`docs/ST-12核心板原理图V1.0.pdf`](ST-12核心板原理图V1.0.pdf)（MD5 0938e12c…，与 gitee 仓库同版）

---

## 一、一句话定位

**一块不用接电脑就能调波形、能上总线、能存故障的伺服驱动器。**

普通学生做 FOC，成果是"电机动了，PC 上看到正弦波"。
这个项目做完，成果是"驱动板自己带屏、自己画波形、自己存数据、挂 CAN 总线能被上位机当从站"。

差别不在控制算法，在**产品形态**。而这块板恰好给了做产品形态的全部零件。

---

## 二、为什么是这块板：资源利用率

先把板子的零件盘一遍，每一样都要有去处，否则就是浪费（也是面试官会问的"你为什么选这块板"）。

| 板载资源 | 接到哪 | 在本项目里的角色 | 缺了会怎样 |
|---|---|---|---|
| **FSMC 并口屏**（2.54 排针 + FPC） | PE7-PE15 / PD0-PD15 / PD11(A16) | **实时波形 + 参数面板** | 只能接电脑看，项目降级成"又一个 FOC demo" |
| **FDCAN2**（板载 TJA1050） | PB12/PB13 | 上位机命令 + 多轴扩展 | 没法讲"总线型伺服" |
| **RS485**（板载 TP8485E） | PB10/PB11 | Modbus RTU 从站 | 少一个工业协议标签 |
| **W25Q128**（16MB SPI Flash） | SPI1 PA4-PA7 | **波形黑匣子**：故障前 10 秒数据 | 故障只能靠"当时看到了"，没法复盘 |
| **AT24C02**（I2C1 EEPROM） | 板载 I2C1 | PID 参数 + 编码器零偏掉电保存 | 每次上电要重新标定 |
| **SD 卡槽**（SDIO） | PC8-PC12 | 长时间录波（可选，P2） | 不影响 |
| **ESP8266 接口** | PB10/PB11（与 485 复用）| 无线调试（可选，P2） | 不影响 |
| **2 个按键** | PA0(WKUP) / PA3 | 本地 启停 / 换模式 | 只能靠总线控制 |
| **LED ×2** | PE0 蓝 / PE1 绿 | 运行 / 故障指示 | 状态不可见 |
| **TIM20**（第三个高级定时器） | PE2/PE3/PF2 | **三相 PWM** | 这是能做 FOC 的前提 |
| **ADC1 ×5 / OPAMP ×6 / COMP ×7** | PA1/PA2/PB0 | 双相电流 + 母线 + 硬件过流 | 只能做电压模式，做不了电流环 |
| **CORDIC + FMAC** | 片内 | sin/cos 与滤波加速 | 20 kHz 余量变紧 |

**结论**：这块板的定位不是"G474 核心板"，是**一块自带 HMI 的电机控制主板**。方案必须把这个优势吃干净。

## 三、系统架构

### 3.1 分层

```
┌──────────────────────────────────────────────────────────┐
│  应用层   task_speed / task_position / task_service       │  ← 与芯片无关
│           can_app / hmi_app（新）                          │
├──────────────────────────────────────────────────────────┤
│  算法层   foc_core（Clarke/Park/PI/SVPWM）                 │  ← 与芯片无关
│           trig（CORDIC 后端可切换）                        │
├──────────────────────────────────────────────────────────┤
│  驱动层   encoder(AS5600) / current_sense(ADC)            │
│           lcd_fsmc（新）/ param_store（EEPROM 新）         │
├──────────────────────────────────────────────────────────┤
│  硬件层   main.c 外设初始化 + port 层                      │  ← 换芯片只改这里
└──────────────────────────────────────────────────────────┘
```

**换芯片只动最底一层**——这条在简历里能讲，因为 F103 → G474 已经验证过一次。

### 3.2 任务表（最终形态 6 任务）

| 任务 | 优先级 | 周期 | 栈 | 职责 |
|---|---|---|---|---|
| **TIM20_UP ISR** | 2(NVIC) | 50 µs | 主栈 | ADC→Clarke→Park→2×PI→SVPWM→CCR |
| Task_Speed | 6 | 1 ms | 256 | 读 AS5600、算电角度、速度 PI → iq_ref |
| Task_Position | 5 | 2 ms | 256 | 位置 P → speed_ref |
| Task_Comm | 4 | 2 ms | 384 | CAN 帧解析 + 串口命令 |
| **Task_HMI** | 3 | 33 ms | 512 | **屏刷新 30 fps**（新） |
| Task_Monitor | 3 | 10 ms | 224 | 母线/nFAULT/堵转/喂狗 |
| Task_Log | 1 | 10 ms | 384 | 任务表打印 + 波形入 Flash |

**新增的 Task_HMI 是重点**：它证明你会做"实时任务的时间预算分配"——刷屏要几十毫秒，绝不能挤占控制环，所以优先级放在监控同级、周期 33 ms，且用**非阻塞分段刷**（每帧只画一部分）。

### 3.3 数据流

```
        ┌────────── 20 kHz 电流环（中断）──────────┐
        │  ADC → Clarke → Park → PI → SVPWM → PWM │
        └───────────────┬──────────────────────────┘
                        │ 写 g_foc（双缓冲快照）
        ┌───────────────┴──────────────┐
        ↓                              ↓
   Task_HMI 30fps                 Task_Log 100Hz
   屏上画三相电流/转速/故障         写 W25Q128 环形缓冲
        ↓                              ↓
   本地看得见                    故障后能复盘
```

**关键设计**：ISR 只写，HMI 只读，中间用**序号+双缓冲**（ISR 写 A 区，HMI 读 B 区，写完翻转），避免任务读到半新半旧的数据。

## 八、简历怎么写

> **带本地 HMI 的 FOC 伺服节点**（STM32G474 + FreeRTOS，独立完成软硬件联调）
> - 基于 TIM20 高级定时器实现 20 kHz 三相 SVPWM，ADC 注入组同步采样双相电流，内置 CORDIC 加速坐标变换（较查表法精度提升 2.5 倍、调用次数从 4 次降至 1 次）
> - FreeRTOS 六任务调度：电流环在中断硬实时，速度环 1 kHz / 位置环 500 Hz / HMI 30 fps 分级调度，实测任务抖动 P99 8.6 µs、CPU 占用 52%
> - 设计 FSMC 屏实时波形界面与 W25Q128 波形黑匣子，故障前 10 s 数据可离线导出复盘
> - 实现 CAN 总线 CiA402 状态机子集（0x6040/0x6041），10 万帧压测零丢帧；三级保护（过流/过压/堵转）响应 ≤ 300 ms，72 h 拷机无复位

**"波形黑匣子"和"本地 HMI"这两条是差异化**，比堆参数管用。

## 九、风险与降级

| 风险 | 概率 | 降级方案 |
|---|---|---|
| FSMC 屏驱动调不通 | 中 | 先用仓库的 `03参考案例/04 2.8寸屏幕显示` 跑通，再改成波形界面；实在不行降级为 OLED（I2C） |
| 电流环震荡调不稳 | 中 | 退回电压模式 FOC（能转能定位，只是没有力矩闭环），简历改写"电压模式 FOC + 速度/位置双环" |
| TIM20 的 AF 配置出问题 | 低 | 备选：改用 TIM1_CH1(PA8) + 飞线到外部三相驱动，只做 1 路 PWM 验证 |
| CORDIC 配置不通 | 低 | `FOC_USE_CORDIC` 改 0，退回查表，功能不受影响 |
| 时间不够 | 中 | **P0 做完就是完整项目**，P1/P2 是加分项，不要为了屏牺牲电流环 |

## 十、执行建议

1. **先跑 P0 的"LED + 串口 + CORDIC 自检"** —— 这一步不接电机、不接驱动，只验证板子和工具链，半小时就能完成，但能排除 80% 的环境问题。
2. **屏放到 W7 再碰** —— 它很诱人，但和控制环无关。提前搞屏，一定会拖慢主线。
3. **每周留一份"能回滚的提交"** —— 调电流环调炸了，能退回上周的状态。
